# Free AI Prompts That Don't Suck — Project Rules

## What This Repo Is

A public collection of battle-tested system prompts for AI coding assistants. Every prompt solves a specific, documented failure mode. No vibes. No fluff.

## Delivery SOP

**Follow `docs/SOP-delivery.md` for all prompt work.** It is the single process document for this repo. Read it before your first delivery. Refer to it during every delivery.

## Structure

```
prompts/<category>/<slug>.md      — Source of truth. One file per prompt.
prompts/<category>/_category.md   — Category description (H1 + one line). Hand-written.
prompts/<category>/README.md      — AUTO-GENERATED category index. Never hand-edit.
install/                          — AUTO-GENERATED by the build. Never hand-edit.
scripts/build.py                  — Build logic (validate, install/, indexes, README table).
scripts/build.sh                  — Thin wrapper; `make build` calls it.
docs/SOP-delivery.md              — Delivery process. Follow it.
docs/taxonomy.md                  — All 33 category charters. Check before placing a prompt.
docs/choosing-prompts.md          — User-facing guide for picking prompts.
```

## Adding a New Prompt

1. Read `docs/SOP-delivery.md` (the full pipeline with quality checklist)
2. Create `prompts/<category>/<slug>.md` with YAML frontmatter and the standard template
3. Run `make build` — generates install files and updates README table
4. Commit everything together (prompt + generated files)

## Rules

### Source of Truth
- `prompts/` is the only place prompt content is authored
- `install/` files are auto-generated — never edit them by hand
- README prompt table is auto-generated between `<!-- PROMPT_TABLE_START -->` and `<!-- PROMPT_TABLE_END -->`
- Run `make build` after any change to prompt files

### Prompt File Requirements
- YAML frontmatter: title, slug, category, tags, works_with, severity, one_liner
- slug must match filename (without .md) and be unique across ALL categories (install files are keyed by slug)
- category must match parent directory name
- one_liner under 80 chars, no `|` characters (it goes into markdown tables)
- Instruction block must exist between two `---` horizontal rules in the body — exactly four `---` lines per file
- `make validate` catches all of these

### Categories
- 33 categories, each with a charter in `docs/taxonomy.md` — check it before placing a prompt
- New categories are just new directories under `prompts/` with a `_category.md`; add the charter to the taxonomy
- Build script discovers them automatically — no config to update
- Keep category names lowercase-kebab-case

### Commits
- `docs(prompts): add <name>` for new prompts
- One prompt per commit when possible; group by category for batch work
- Generated files go in the same commit as the source prompt (or a final build commit in the same push for large batches)
- Never commit install/ changes without corresponding prompts/ changes

## Tone
- Direct. No hedging.
- Written for practitioners.
- If it's true and it's funny, say it.
- Evidence over vibes. Every prompt traces back to a real failure.
