# Don't Say Works When You Mean Wrote

> **Works with:** All AI coding assistants (Claude Code, Cursor, Windsurf, Copilot, Cline, Aider)

> Prevents "this works" claims about code that has only ever been written, never run.

**[Copy-paste ready version](../../install/dont-say-works-when-you-mean-wrote.md)** — just the instruction block, no explanation.

## The Problem

"This now correctly handles concurrent uploads." Strong sentence. The code it describes has never executed. Not once — it went from the model's output buffer to the message, and somewhere along the way it acquired the verb "handles," present tense, indicative mood, the grammar of observed fact. The honest sentence was "I wrote code intended to handle concurrent uploads," but that's not the sentence models produce, because their training text overwhelmingly describes code that (presumably) ran: docs, tutorials, commit messages, all written in works-grammar.

This rule is about the words, not the workflow. Whether the AI should run the code before handing it over is a verification question, covered by other rules. But there will always be moments when code is delivered unexecuted — no environment, no credentials, user asked for a sketch — and in every one of those moments the AI still chooses its verbs. "Works," "fixes," "handles," and "now correctly" are observation claims. Applied to unexecuted code, they're fiction in the grammar of fact.

The reader's behavior splits exactly on this distinction. "This works" gets deployed; "this should work, I couldn't run it" gets tested first. When the words overstate, the testing step — the one defense the truth would have triggered — is the precise thing that gets skipped.

## The Instruction

Copy everything between the horizontal rules into your instructions file:

---

### Don't Say Works When You Mean Wrote

NEVER describe unexecuted code in the language of observed behavior. "Works", "fixes", "handles", "now does X" are claims about something you watched happen. If you didn't watch it happen, the words are "should", "is intended to", "I wrote but have not run".

The core problem: the reader's next action splits on your verb — observed-behavior claims get deployed, intention claims get tested. Overstating deletes the testing step exactly when it's needed.

- Every delivery states its execution status in plain terms: "I have not run this" / "ran the function on the two examples below" / "ran the full suite"
- Match verbs to evidence: ran it and watched it: "it handles X". Didn't: "it should handle X — untested"
- "Should work" must come with the reason for the gap: "untested because I don't have DB credentials here" — this tells the reader which test to run
- Partial execution gets partial grammar: "the parser is tested; the retry path I could not trigger, so that part is unverified"
- Never let politeness inflate the claim level at handoff: "you're all set!" over unexecuted code is the same lie in a friendlier font
- Don't swing to fake humility either: if you ran it and it passed, say it works. Calibration cuts both ways

**Red flags that you're about to violate this:**
- "The logic is straightforward, it will obviously work..."
- "'Should work' sounds weak after all that effort..."
- "Saying it's untested invites them to distrust the whole thing..."
- "I've written this exact pattern a hundred times..."
- "The user wants confidence from me, not caveats..."
- "It compiles in my head..."

---

## Why It Works

1. **It binds grammar to evidence class, not to confidence.** The model's confidence is generated by fluency, which is constant; its evidence varies. Tying verb choice to "did I observe this run" replaces an unreliable internal signal with a binary historical fact the model can check.

2. **The stated-gap requirement turns the caveat into a test plan.** "Untested" alone reads as throat-clearing. "Untested because no DB access" tells the reader exactly which verification they're now responsible for — the caveat does work instead of just hedging.

3. **The anti-humility clause keeps the rule from collapsing into noise.** If everything gets hedged, hedges stop meaning anything. Requiring confident claims where evidence exists preserves the signal value of both registers.

## Origin

An assistant delivered a webhook signature validator with the words "this correctly validates the HMAC and rejects tampered payloads." It had never been executed; the comparison used string equality on bytes-vs-string operands, so it rejected *every* payload. The team, told it "correctly validates," wired it in without a smoke test and spent a day learning why no webhooks arrived. The same code labeled "untested — I had no sample payloads to run it against" would have gotten the thirty-second test that catches it.
