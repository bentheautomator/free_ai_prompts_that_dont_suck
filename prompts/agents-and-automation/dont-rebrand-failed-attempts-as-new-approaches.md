# Don't Rebrand a Failed Attempt as a New Approach

> **Works with:** All AI coding assistants (Claude Code, Cursor, Windsurf, Copilot, Cline, Aider)

> Prevents the agent from disguising a retry loop as exploration by making cosmetic tweaks between attempts.

**[Copy-paste ready version](../../install/dont-rebrand-failed-attempts-as-new-approaches.md)** — just the instruction block, no explanation.

## The Problem

The sophisticated version of the retry loop doesn't repeat the command verbatim — it dresses each repeat up as a fresh idea. The install fails, so the agent tries it with `sudo`. Then with the flags in a different order. Then with single quotes instead of double. Then from a different directory. Each attempt gets narrated as "let me try a different approach," and each one fails for the exact same underlying reason, because none of them addressed the underlying reason.

This pattern is harder to catch than verbatim looping precisely because the surface keeps changing. The agent genuinely believes it is exploring. But quoting style was never the hypothesis — there was no hypothesis. The variations are generated by reaching for whatever knob is nearest, not by reasoning about why the failure happened. A session can chew through twenty of these "approaches" and an hour of runtime while standing perfectly still.

The tell is that the error message never changes. Twenty syntactic costumes, one identical stack trace. A human watching the transcript spots it in seconds; the agent, narrating each attempt as novel, never does.

## The Instruction

Copy everything between the horizontal rules into your instructions file:

---

### Don't Rebrand a Failed Attempt as a New Approach

NEVER count a cosmetic variation as a new approach. Changing quotes, flag order, working directory, or adding `sudo` to a command that just failed is the same attempt wearing a different shirt.

The core problem: variation feels like exploration, so a retry loop with costume changes never registers as a loop. An approach is only new if it rests on a different hypothesis about why the previous one failed.

- Before any variant attempt, name the hypothesis: "I believe the failure was caused by X, and this change addresses X." No hypothesis, no attempt.
- If the error message is identical to the previous attempt's, your variation did not address the cause. Do not generate another variation — go read the error properly and investigate.
- Adding `sudo` is not an approach; it is an admission you haven't diagnosed a permissions issue. Diagnose it: whose file, what mode, why are you being denied?
- Cap genuinely distinct approaches at three. If three different hypotheses have each failed, the problem is something you haven't understood yet. Stop, summarize the three hypotheses and their results, and report to the user.
- Keep a running list in your reasoning of approaches tried and why each failed. Consult it before every new attempt so you don't re-try a relabeled version of attempt one.

**Red flags that you're about to violate this:**
- "Let me try a slightly different syntax..."
- "Maybe with sudo it'll work..."
- "I'll try the same thing from the parent directory..."
- "Perhaps escaping it differently will help..."
- "Let me try yet another approach..." (when you can't say what was wrong with the last one)

---

## Why It Works

1. **It redefines "approach" with teeth.** The loophole that powers this failure is a fuzzy definition of novelty. Pinning "new approach" to "new hypothesis about the cause" makes the cosmetic variants ineligible by definition.

2. **It uses the error message as an objective loop detector.** The agent's narration says "different approach"; the identical error text says "same attempt." The rule tells the agent which signal to trust.

3. **It puts a ceiling on genuine exploration too.** Three real hypotheses failing means the agent's model of the problem is wrong, and hypothesis four drawn from the same wrong model won't save it. The cap forces escalation while there's still budget left to act on it.

4. **It targets `sudo` by name.** The single most common costume change gets called out specifically, so the agent can't reach for it reflexively.

## Origin

Asked to fix a failing Docker build, an agent spent fifty minutes trying the build command with `sudo`, with `--no-cache`, with the context path quoted, from the repo root, from the subdirectory, and with the Dockerfile path made absolute — eleven "approaches" in total, every one producing the same `COPY failed: file not found` error. The actual problem was a typo'd filename in the Dockerfile, discoverable by reading the one line the error pointed at. The human who took over fixed it in under a minute.
